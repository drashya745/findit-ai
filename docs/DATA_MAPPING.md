# Dataset ingestion: source → canonical mapping

Source: `data/raw/lost_found_dataset_realistic_metadata_30k.csv`, a read-only, byte-identical
copy of the original file (SHA-256 `117f9294…567730`). The original in the project root is
untouched. The mapping lives in `config/dataset_mapping.conf`; no source column names are
hardcoded in C++.

## Column mapping

| Canonical field | Source column | Required | Normalization | Output column (`reports.csv`) |
|---|---|---|---|---|
| `source_id` | `item_id` | optional (fallback `line:<n>`) | trim | `source_ref` |
| `report_type` | `lost_or_found` | yes | trim, case-insensitive match against `report_type.lost/found` | `report_type` (`LOST`/`FOUND`) |
| `category` | `item_name` | yes | trim, collapse whitespace; case kept | `category` |
| `description` | `description` | yes | trim, collapse whitespace; **wording, case, typos and slang kept** (`L0st`, `lol`) | `description` |
| `color` | `color` | yes | trim, lowercase | `color` |
| `brand` | `brand` | optional | trim; `None`/`null`/`nan`/`n/a`/`na`/empty → unknown (empty) | `brand` |
| `location` | `location` | yes | trim, collapse whitespace | `location` |
| `reporter` | `user` | optional (fallback placeholder user) | trim; one `User` per distinct name (case-insensitive), IDs `U001…` in first-seen order | `reporter_id` (+ `users.csv`) |
| `timestamp` | `timestamp` | yes | `YYYY-MM-DD[ HH:MM[:SS]]`; date kept, time used only for profiling | `date` |
| *(none)* | — | — | app-managed lifecycle, starts `OPEN` | `status` |
| *(none)* | — | — | not in dataset; empty | `held_at` |

`report_id` (`R000001…`) is assigned in accepted-row order. Because every row was accepted,
`R0xxxxx` currently equals `item_id` = xxxxx, but **use `source_ref` for traceability**, not
that coincidence.

## Report type

The source has an explicit `lost_or_found` column with only the values `lost` and `found`, so
every row has enough evidence for `LostReport` or `FoundReport`. Rows with any other value are
rejected (`invalid_report_type`), never guessed.

**If a future dataset has no type column:** do not infer lost/found from wording ("found a…").
The safe alternative is to stop at ingestion: the adapter already refuses to start when the
required `report_type` column is missing. Add a third, quarantined "unclassified" output that is
excluded from matching until a human labels it.

## Validation and rejection

Each rejected row goes to `data/processed/rejected_rows.csv` with its line, source ID, reason
code, detail and raw record. Reason codes:
`malformed_csv`, `wrong_field_count`, `missing_required_field`, `invalid_report_type`,
`invalid_timestamp`, `duplicate_row` (exact duplicate), `duplicate_source_id` (same `item_id`,
later row rejected), and `validation_failed` (domain rules, e.g. description < 10 chars).
Rows identical except for `item_id` are **kept** and counted (`same_content_different_source_id_kept`).

## Outputs (`data/processed/`, regenerated by `./build/findit_ingest`)

`users.csv`, `reports.csv`, `rejected_rows.csv`, `summary.json`. Files are written atomically.
The summary contains no wall-clock time, so re-running produces byte-identical files.
`findit_ingest` refuses to write into the input file's directory.
Reports created in the CLI are appended to `data/store/reports.csv`; the processed baseline is
never edited.
